# المعمارية المقترحة

## التطبيقات
- `apps/abqari_edu`: تجربة تعلم منظمة: مسارات، دروس قصيرة، أمثلة محلولة، تدريب متدرج، اختبارات، متابعة تقدم.
- `apps/abqari_math`: إدخال المسائل، الحل الرمزي والعددي، التحقق، الشرح، الرسوم والهندسة، أدوات الرياضيات المتقدمة.

## المكتبات المشتركة المقترحة
- `packages/shared_ui`: عناصر الواجهة والسمات.
- `packages/localization`: النصوص والترجمة وRTL/LTR.
- `packages/math_input`: محرر المعادلات والتعبيرات.
- `packages/math_engine`: واجهة موحدة لمحركات الحل والتحقق.
- `packages/geometry`: نماذج وأدوات الهندسة.
- `packages/quiz`: بناء الأسئلة والتقييم.
- `packages/learning_core`: المهارات والمتطلبات السابقة وتتبع التقدم.

لا تُنشأ هذه الحزم كحزم وهمية؛ أضف كل حزمة عند وجود تنفيذ واختبارات لها.

## الخادم
يوصى بطبقة API خلفية وقاعدة PostgreSQL (مثل Supabase عند اختياره وإعداده). تتولى:
- المصادقة وإدارة الأدوار.
- سياسات الوصول إلى بيانات المستخدمين والطلاب.
- تخزين المحتوى والتقدم والاختبارات.
- تمرير طلبات الذكاء الاصطناعي إلى مزود خارجي بأمان.
- تنفيذ أو تنسيق عمليات الحل والتحقق.

## محرك الرياضيات
افصل بين:
1. تحليل المدخلات وتطبيعها.
2. اختيار طريقة الحل أو المحرك.
3. إنتاج خطوات مفهومة.
4. التحقق بالتعويض أو بمحرك رمزي/عددي مستقل.
5. عرض حدود الثقة أو التنبيه عند تعذر التحقق.

يمكن تقييم SymPy في خدمة Python خلفية للعمليات الرمزية. لا تفترض أن النموذج اللغوي بديل عن محرك رياضي.

## المحتوى
هيكل EDU المقترح:
`مجال ← موضوع ← مهارة ← مستوى إتقان ← درس/نشاط ← سؤال`
مع وسوم للصعوبة والوقت المتوقع والمتطلبات السابقة. لا توجد حقول إلزامية للدولة أو المنهج أو الفصل الدراسي.

## الأمان والخصوصية
- فرض RLS/صلاحيات الخادم على كل بيانات المستخدمين.
- عزل بيانات كل مستخدم/صف/مجموعة حسب الصلاحية.
- جمع الحد الأدنى من بيانات الطلاب.
- عدم تسجيل أسرار أو صور مسائل حساسة في السجلات.
- مراجعة حماية بيانات القاصرين قبل الإطلاق.
